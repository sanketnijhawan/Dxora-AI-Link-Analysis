# AI-Powered Website Link Analysis API

Python/FastAPI solution for the Dxora Technologies practical test. It accepts a public website URL, fetches the **submitted HTML page**, extracts readable business information, asks Gemini to create a structured report, and validates the report with Pydantic.

> **Status:** Source code and offline automated tests are ready. A live Gemini call and public deployment are **not** claimed or demonstrated here because no user API key or hosting credentials were provided. The sample output is a synthetic test fixture, not a real analysis. Review and validate live output before submission.

## API

`POST /link-analysis` on port `4000` (interactive docs at `/docs`).

**Request**

```json
{"url":"https://example.com"}
```

**Response**: `success`, `website`, `brand`, `analysis`, and `metadata`. The `analysis` object always includes:

1. `competitor_analysis`: brand overview, potential competitors, strengths and opportunities. Suggested competitors are explicitly **unverified**, not presented as researched facts.
2. `target_search_queries`: exactly five suggested queries collectively covering Google, Facebook, Instagram, LinkedIn and X, with intent, relevance and target audience. No invented search volumes.
3. `seo_improvements`: primary, secondary, long-tail and related keywords; suggested title, meta description and supporting content.
4. `top_services`: exactly five observed or **suggested** services, clearly labeled with `source_basis`.
5. `target_audience`: audience groups, industries, business types, needs, interests, geographic focus (if known), marketing segments.

`metadata.evidence` gives the fetched page's title, meta description, headings and approximate word count, so the user can assess what was actually read.

### Local setup

Requirements: Python 3.10+ and a Gemini API key associated with an account that can call the chosen model.

**Windows PowerShell**

```powershell
py -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements-dev.txt
Copy-Item .env.example .env
# Edit .env and set your real GEMINI_API_KEY
python -m pytest -q
uvicorn app.main:app --host 0.0.0.0 --port 4000
```

**macOS/Linux**

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements-dev.txt
cp .env.example .env
# Edit .env and set your real GEMINI_API_KEY
python -m pytest -q
uvicorn app.main:app --host 0.0.0.0 --port 4000
```

Then visit <http://localhost:4000/docs> and execute the endpoint, or use:

```bash
curl -X POST http://localhost:4000/link-analysis \
  -H 'Content-Type: application/json' \
  -d '{"url":"https://example.com"}'
```

For a richer real example, try a public HTML product/company homepage that permits automated access. Some sites block bots or render most content in JavaScript; those limitations are intentionally not hidden.

### Response examples and errors

See [`docs/sample-response.json`](docs/sample-response.json) for an **illustrative fixture-only** response that was generated by the offline test data. It is not the result of a live Gemini call.

| Case | HTTP status | Behavior |
|---|---:|---|
| Valid website and successful LLM analysis | 200 | Five structured analysis sections |
| Malformed URL / missing `url` | 422 | Pydantic validation error |
| Local/private IP, unusual port, redirect, non-HTML or oversized page | 422 | Safe rejection |
| Inaccessible public website | 502 | `Website could not be fetched securely` or upstream HTTP error |
| API key missing/invalid, quota exhausted | 503 | Configuration / provider detail without key leakage |
| Provider failure, invalid model JSON | 502 | Safe upstream error |
| Provider timeout | 504 | Explicit timeout error |

### How it works

1. Pydantic validates the input URL.
2. The URL validator refuses file/local hostnames, embedded credentials and nonstandard ports.
3. The async DNS resolver rejects private, loopback, link-local, multicast and reserved addresses (including *mixed* public/private DNS answers). The HTTP connector is **pinned to validated IPs**, protecting the connection from a DNS rebind between validation and fetch. Proxy settings are ignored and redirects are disabled.
4. The HTML fetch enforces a 13-second timeout, 750 KB size limit, `text/html` content type and a one-page scope.
5. BeautifulSoup removes navigation, scripts and other noise, collects title, meta description, headings and JSON-LD, and caps text passed to the model at 12,000 characters.
6. The model receives an explicit untrusted-content boundary, a JSON schema and instructions not to treat on-page text as commands.
7. Gemini's JSON response is validated against typed Pydantic models; missing required sections, unsupported platforms, incorrect counts, and unsupported 'verified competitor' claims are rejected. The endpoint returns a clear upstream error instead of a fabricated fallback report.

**Important limitations:** The application analyzes **one HTML page**, not a full website. It does not perform a Google/social search or independent competitor fact-checking. AI-proposed competitors must be externally validated; their strengths/gaps are hypotheses. A brand with fewer than five listed services may receive explicitly labeled *suggested* service opportunities. The model can still hallucinate plausible statements; Pydantic checks shape, not every claim's factual truth. Public requests are not subject to user authentication, rate limiting or persistent caching in this MVP; add those before deploying openly for extended use.

## Model comparison and research (checked November 20, 2026)

These are **published standard API text rates**, USD per million input/output tokens, excluding extra tools and third-party hosting. Prices can change. None of these models has been benchmarked on this particular dataset here.

| Provider | Model | Input / 1M | Output / 1M | Context | Structured JSON | Speed/accuracy assessment |
|---|---|---:|---:|---|---|---|
| Google | `gemini-3.1-flash-lite` | $0.25 | $1.50 | ~1M | Native JSON output mode plus local Pydantic validation | Designed for cost-efficient processing; **not timed or accuracy-scored here** |
| Anthropic | `claude-haiku-5-5` | $0.10* | $0.50* | 1M | Supports structured output through provider API; requires a separate adapter | Provider positions it for latency-sensitive extraction; **not benchmarked here** |
| OpenAI | `gpt-5.4-mini` | $0.75 | $4.50 | 400K | Structured outputs through API; requires a separate adapter | Higher listed token price; quality and latency for this task **not benchmarked here** |

\* Haiku 5.5 prices apply to prompts up to 100K input tokens; longer prompts have higher rates.

**Primary implementation:** Gemini 3.1 Flash-Lite. Rationale: straightforward REST `generateContent` JSON output mode, low standard pricing, sufficient context, and one typed-validation path. This is an **engineering choice**, not proof that it is the most accurate or fastest. **Cost-first fallback model to evaluate:** Claude Haiku 5.5, whose listed token rates are lower for short prompts. The fallback is a *recommendation*, not a secretly implemented automatic provider switch.

**Illustrative cost:** Assuming **6,000 input + 3,000 output tokens per completed analysis** (estimates only; actual usage varies), excluding grounding and taxes:

| Model | Computation | Estimated USD / site |
|---|---|---:|
| Gemini 3.1 Flash-Lite | 6,000 × 0.25/1M + 3,000 × 1.50/1M | **$0.0060** |
| Claude Haiku 5.5 (short prompt) | 6,000 × 0.10/1M + 3,000 × 0.50/1M | **$0.0021** |
| GPT-5.4 mini | 6,000 × 0.75/1M + 3,000 × 4.50/1M | **$0.0180** |

**Speed:** No provider-side live measurements have been made. A single real request may take seconds to tens of seconds depending on token count, model load and network conditions. The app currently caps the Gemini call at 35 seconds, and the website fetch at 13 seconds. Those are **configured timeout limits, not measured average response times**.

**Accuracy:** No benchmark result is claimed. To select a production model, run all three models over the same 20–30 real sites, blind-score service grounding, competitor claim quality, SEO usefulness, JSON validation rate, p50/p95 latency and actual token cost. The winning model must be selected from those measurements, not marketing claims.

### Cost controls and improvement ideas

- Fetch one page, strip boilerplate and cap extracted input length.
- Make one LLM request for all five report sections, not five separate requests.
- Minimize repeat calls; for production, cache by URL + content hash for a limited TTL.
- Track actual input/output token counts and latency from provider responses; alert when costs change.
- Retry only transient failures with exponential backoff in a later production version, never silently return invented data.
- Optionally use a small model for entity extraction and a stronger model for difficult competitor research after measuring value.
- Verify competitor facts through credible external sites/search APIs when available; this application does **not** do that.

## Deployment

A minimal `Dockerfile` is included for cloud deployment. Configure `GEMINI_API_KEY` as a **secret environment variable** in the hosting dashboard (never in Git). The app listens on `${PORT:-4000}`. Once deployed, check:

- `https://YOUR-HOST/docs`
- `POST https://YOUR-HOST/link-analysis` with a real public URL

Do **not** put the `.env` file, keys or tokens on GitHub. An API key and hosting account are required before a public demo can honestly be provided. For a production public deployment, add authentication and request rate limits to avoid unbounded LLM billing.
